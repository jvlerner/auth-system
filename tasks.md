Sem nenhum framework de mock externo.
- [2026-03-18] - [Testes] - Testes Unitários `ProcessUserRegistrationUseCase` e `UpdateUserRolesUseCase`: 7 cenários adicionais implementados com mocks in-memory dedicados por test-suite. Cobertura: payload malformado, email inválido (descarte idempotente), usuário duplicado (poison-message prevention), falha no hasher (NACK), registro bem-sucedido, usuário não encontrado no update roles e emissão de evento no Outbox. Total de 12 testes unitários no pacote application.
- [2026-03-18] - [Testes] - Testes Unitários `LoginUserUseCase`: 5 cenários implementados com mocks 100% in-memory sem frameworks (mockUserRepo, mockHasher, mockTokenGen, mockOutbox + miniredis). Coberturas: email inválido, usuário não encontrado, senha incorreta, sucesso completo e detecção de hash legado com emissão do evento de upgrade via outbox.
- [2026-03-18] - [Infra] - Health Probes Cloud-Native: Criado pacote `pkg/health` com `LivenessHandler` (lightweight, 200 OK imediato) e `ReadinessHandler` (verifica PostgreSQL e Redis com timeout de 3s, retorna 503 se degradado). Handlers adicionados ao `api-write` nas rotas `/health/live` e `/health/ready`. Design genérico com `ReadinessCheckers` permite reutilização em `api-read`, `worker-events` e outros serviços sem duplicação.
- [2026-03-18] - [Feature] - Versionamento Dinâmico de Hash de Senhas: Refatorado o microserviço `grpc-password` para arquitetura polimórfica. Extraída a interface `HashService` com implementação `PasswordServiceV1` (Argon2id, prefixo `v1:`). O `GrpcServer` agora funciona como router detectando a versão pelo prefixo e sinalizando `NeedsUpgrade` quando o hash está num versão inferior à `currentVersion`. O `LoginUserUseCase` detecta o sinal, gera o novo hash (v2) via gRPC e persiste via Outbox sem trafegar plaintext. Worker consome `UserPasswordUpgradeRequested` e atualiza a senha no banco transparentemente.
- [2026-03-18] - [Feature] - Rate Limiter (Anti-Brute Force): Módulo de limitação e segurança implementado através de Redis INCR e Fixed Window. Sub-grupos de rotas criados no `api-write` aplicando engessamento agressivo via Header e IP real nas rotas de `login`, `register`, `forgot-password` e `reset-password` devolvendo `429 Too Many Requests`.
- [2026-03-18] - [Feature] - Refresh Tokens Opacos: Implementado o fluxo de Rotação de Referência utilizando Redis. O Use Case `LoginUserUseCase` agora gera um token UUID salvando no Redis com TTL de 7 dias. Adicionado `RefreshTokenUseCase` que troca tokens atrelados ao usuário por novos JWT assemétricos sem requalificar senha, além da rota `LogoutUseCase` garantindo que o ciclo da sessão seja truncado remotamente (Single Sign-Out).
- [2026-03-18] - [Feature] - Esqueci minha senha: Fluxos de requisição e redefinição de senha criados (CQRS). A rota `/api/v1/commands/forgot-password` emite `UserForgotPasswordRequested` para o Outbox. O `worker-events` gera tokens de curta duração no Redis. A rota `/api/v1/commands/reset-password` valida o token assíncronamente, realiza re-hash gRPC da nova senha, atualiza o DB e destrói (burn-after-reading) a chave no Redis pra segurança.
- [2026-03-18] - [Feature] - Confirmação de E-mail: Implementada a geração de eventos via Transactional Outbox. O `worker-events` gera tokens temporários no Redis e emula disparo de link. A API Write valida o código na rota `/api/v1/commands/confirm-email` setando a flag `email_verified=true` de forma State-Driven.
